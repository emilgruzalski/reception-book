# ReceptionBook – Backend

REST API for **ReceptionBook**, a web application for hotel reception staff: rooms, guests, reservations,
check-in / check-out and employee accounts.

The project was created as part of the engineering thesis
*„Architektura i bezpieczeństwo nowoczesnych aplikacji internetowych na przykładzie aplikacji ReceptionBook”*.

The Angular client lives in the [ReceptionBook-Frontend](https://github.com/emilgruzalski/ReceptionBook-Frontend) repository.

## Features

- Rooms with types, capacity, price and status (available, occupied, cleaning, out of service)
- Guests with search by name, document number, e-mail or phone
- Reservations with availability check, price calculation, check-in, check-out and cancellation
- Dashboard with today's arrivals, departures and occupancy
- Employee accounts with roles: **Administrator** and **Receptionist**
- Paging, filtering, searching and sorting of lists (`X-Pagination` response header)

## Architecture

The solution follows a layered (onion) architecture. Each layer depends only on the layers below it.

| Project | Responsibility |
| --- | --- |
| `ReceptionBook` | Host: `Program.cs`, configuration, middleware, migrations |
| `ReceptionBook.Presentation` | API controllers and action filters |
| `Service.Contracts` / `Service` | Business logic and service interfaces |
| `Contracts` / `Repository` | Data access with Entity Framework Core (repository + unit of work) |
| `Entities` | Domain models, exceptions and configuration models |
| `Shared` | DTOs and request parameters |
| `LoggerService` | Logging with NLog |
| `ReceptionBook.Tests` | Unit tests (xUnit, Moq, FluentAssertions) |

## Security

- Authentication with **JWT access tokens** (15 min) and **refresh tokens** (7 days) with rotation and revocation on logout
- Refresh tokens are stored only as **SHA-256 hashes** and compared in constant time
- **ASP.NET Core Identity** with a strong password policy and **account lockout** after 5 failed attempts
- **Role-based authorization** on every endpoint; only administrators can manage rooms and users
- **Rate limiting** – a strict limit for login and token endpoints, a global limit per IP address
- Input validation of all DTOs; whitelisted properties for dynamic sorting
- Global exception handler that never returns stack traces or internal error details
- Security headers (`Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`), HSTS, no `Server` header
- CORS limited to configured origins, methods and headers
- No secrets in the repository – user secrets for development and environment variables in Docker
- Parameterized SQL queries generated by EF Core

.NET 8, ASP.NET Core Web API, Entity Framework Core 8, SQL Server, ASP.NET Core Identity, JWT Bearer,
AutoMapper, NLog, System.Linq.Dynamic.Core, Swagger (Swashbuckle), xUnit, Moq, FluentAssertions, Docker.

## Getting started

Requirements: [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0), SQL Server (e.g. in Docker) and the
`dotnet-ef` tool (`dotnet tool install --global dotnet-ef`).

1. Start SQL Server:

   ```bash
   docker run -e "ACCEPT_EULA=Y" -e "MSSQL_SA_PASSWORD=<db-password>" -p 1433:1433 -d mcr.microsoft.com/mssql/server:2022-latest
   ```

2. Set the secrets (they are stored outside the repository):

   ```bash
   cd ReceptionBook
   dotnet user-secrets set "ConnectionStrings:sqlConnection" "Server=localhost,1433;Database=ReceptionBook;User Id=sa;Password=<db-password>;TrustServerCertificate=True"
   dotnet user-secrets set "JwtSettings:SecretKey" "$(openssl rand -base64 48)"
   dotnet user-secrets set "AdministratorAccount:Password" "<admin-password>"
   ```

   The administrator password must have at least 12 characters, upper and lower case letters, a digit and a special character.

3. Create the database and run the API:

   ```bash
   dotnet ef database update
   dotnet run --launch-profile https
   ```

   Swagger UI is available at <https://localhost:7285/swagger>. Log in as `admin` with the password from step 2.

## Docker

```bash
cp .env.example .env   # fill in DB_PASSWORD, JWT_SECRET_KEY and ADMIN_PASSWORD
docker compose up --build
```

The API is available at <http://localhost:8080> and applies database migrations on startup.
Health check: <http://localhost:8080/health>.

## API overview

| Method | Endpoint | Role |
| --- | --- | --- |
| POST | `/api/authentication/login` | anonymous |
| POST | `/api/authentication` (register user) | Administrator |
| POST | `/api/authentication/change-password` | any |
| POST | `/api/token/refresh`, `/api/token/revoke` | anonymous / any |
| GET | `/api/rooms`, `/api/rooms/{id}`, `/api/rooms/available` | any |
| POST, PUT, DELETE | `/api/rooms` | Administrator |
| PUT | `/api/rooms/{id}/status` | any |
| GET, POST, PUT | `/api/guests` | any |
| DELETE | `/api/guests/{id}` | Administrator |
| GET, POST, PUT | `/api/reservations` | any |
| POST | `/api/reservations/{id}/check-in`, `/check-out`, `/cancel` | any |
| DELETE | `/api/reservations/{id}` | Administrator |
| GET | `/api/dashboard` | any |
| GET, PUT, DELETE | `/api/users`, POST `/api/users/{id}/unlock` | Administrator |
